# 子 Agent 专项验收（2026-09-18）

目标版本：`1.8.111+241`。范围为 Flutter App 的 Codex 子 Agent 协议、状态、缓存、父子导航和界面。
使用当前服务器已有 Provider URL/Key 进行真实 API 测试，另以可控事件验证异常与竞态；未修改原配置、
用户已有会话、签名或云端触发规则。OpenCode 当前未声明 subAgents 能力，本次不伪造该能力。

## 修复内容

- 标准协作事件按多个接收者分别显示；同名子 Agent 按 thread ID 独立，后续状态更新保留名称。
- 正确处理真实 `subAgentActivity.completed`，空目标 wait 不产生假智能体，创建失败不显示准备中。
- 父任务结束、最终答案或停止不再把子任务全部判成完成；子新回合可恢复运行，旧回合迟到消息不能覆盖它。
- 新的 sendInput / resumeAgent 可在同一父回合重新激活子任务；无明确重启的迟到活动保留终态保护。
- 返回父会话保留最新审批、恢复期间编辑的草稿/模型/思考强度/附件；恢复失败保留子页面的新输出。
- 修复嵌套返回途中断线重连后返回栈卡住，以及父子页面工作区 diff 串页。
- 历史过滤先统一秒/毫秒时间戳，避免继承父会话历史混入子会话。
- 子 Agent 标签和输入区权限按钮适应窄屏与 1.8 倍字体，长按可查看完整 Agent 路径。

## 边界与返工

“全部情况”按上表可重复的场景验收，不代表穷尽所有服务端版本、网络故障和手机厂商后台限制。
未制造真实 Provider 500/限额错误；这类异常用模拟协议验证。真实 API 只执行短任务，未运行压力测试。

真实测试前两次分别遇到父任务等待超时：一轮的 120 秒不足以完成嵌套调用，另一轮证明子任务中断后父
wait 工具仍可能等待。测试随后改为确认父子独立状态，再显式结束测试父回合并继续原子任务；没有修改
Codex 自身的等待策略，也没有在 App 中自动替用户发消息或停止父任务。

API 统计只保存服务端返回的 token 信息，早期尝试未完整采集，不能给出本轮精确账单。临时认证目录已经
销毁；提交文件已检查不含当前 API Key。没有创建标签或触发云端构建。

Widget fixture 的异步清理、事件排空与点击重建曾返工；实际找到的缺陷先有失败回归再修复。
